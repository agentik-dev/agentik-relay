The one-sentence design: `relay` is a static Go binary whose core is two pure state machines (a night over a queue, a sitting over a packet); every effect (git, the claude process and its stream, the clock, files, the terminal, notify) sits behind an interface with a fake, so `plan` and `run` are one code path with the effects swapped; the binary knows no plugin, and `plugin/` adapts it to Claude Code (R25-90, R25-91 (3)).

## §1 The state machine

Two machines in `internal/relay`, both pure: `Step(s State, e Event) (State, error)` for a sitting and `NightStep(s NightState, e NightEvent, r StopReason) (NightState, error)` for the night. Effects are owed on entering a state (`Actions(s State) []Action`, Moore-style), performed by the loop, which feeds the outcome back as the next event. An illegal pair returns `ErrIllegal` and keeps the state; any event on a terminal state returns `ErrTerminal`; the loop discards late events for terminal sittings (a killed child's exit).

**Sitting states** (eleven): `waiting` (a dependency unsatisfied) → `ready` → `planned` (packet parsed, baseline recorded, spawn argv rendered; `plan` stops here) → `staged` (worktree and branch exist, the refusing pre-push hook installed, the `stage` ledger line written) → `running` (the child is alive) → `exited` (the child is gone) → `paused` (the account's limit paused the night on this part: no child; its tree, stage lock and `Staged` kept; AR64, usage-limit-resume r1 §2) → terminal `green` (gate green; `MergeSHA` set when the policy merged), `red` (gate red: a packet failure), `failed` (a sitting failure, `Reason` set), `skipped` (parked, a dependency red or failed, no progress, or the night halted first).

**Sitting events** (sixteen, `limited` the last) and the legal table; every other pair is `ErrIllegal`:

| state | event → next |
|---|---|
| waiting | `deps-satisfied` → ready; `deps-failed` → skipped; `halt` → skipped |
| ready | `plan` → planned; `invalid` → skipped; `halt` → skipped |
| planned | `stage` → staged; `halt` → skipped |
| staged | `spawn` → running; `exit-error` → failed (spawn failure) |
| running | `stream` → running; `exit` → exited; `exit-error` → failed; `ceiling-hit` → failed (the action: kill the child) |
| exited | `gate-green` → green; `gate-red` → red; `gate-failed` → failed; `gate-unrun` → red, reason `gate-unrun` (an unrun gate is never a pass: the night moves on and the resume line prints; AR4); `limited` → paused (AR64) |
| paused | `spawn` → running (a continuation); `halt` → failed, the loop setting `usage-limit` (a night that ends paused; AR64); `gate-green` → green; `gate-red` → red; `gate-failed` → failed; `gate-unrun` → red (a sibling killed in its gate lands that gate's verdict, as exited does; AR70) |

`failed` reasons are stop reasons: `stream-error` (is_error, no result event, spawn failure), `no-commit`, `dirty-tree`, `ceiling-kill`, `wall-clock`, `origin-moved`, `load` (AR10 §15: the breaker still open before a spawn), `invariant` (AR10 §15: a runtime invariant broken at the sitting line or the gate), `orphans` (AR10 §15: the child's group outlived three kills), `usage-limit` and `auth` (run 10 ruling 1: the account's limit or login; every running row is killed and reads `failed` with the same reason, no worktree is removed). Actions on entering: planned → record the plan; staged → worktree, hook, ledger; running → spawn and stream; exited → the gate; paused → ledger (the `sitting` line; the notice is the night's `pause` line's); green → ledger, merge when the policy says so, notify; red, failed, skipped → ledger and notify.

**Night states:** `planning` → `running` → `draining` (`relay stop`: no new sitting; the running ones finish) → one named terminal state per stop reason, `stopped:<reason>`. A running night's `limited` steps it to `paused:usage-limit` (live, not terminal; AR64, usage-limit-resume r1 §2), which holds rows: `limited` (a later hit), `sitting-green` and `sitting-red` (rows outside a model's scope run on, and a paused sibling's verdict lands, AR70) keep it paused; `wake` → running; `owner-stop` → `stopped:owner-stop` (no draining while paused); `owner-kill` → `stopped:owner-kill`; `until` → `stopped:until-reached`; `budget` → `stopped:budget-reached`; `sitting-failed` with a sitting failure → `stopped:<reason>`; it refuses `planned`, `queue-empty`, `count`, `blocked`, `origin-moved`, `tmux-gone` and `drained`, planning and draining refuse `limited`, and only paused takes `wake`. The loop steps `limited` at a pause and, while paused, `owner-kill` (a signal; `relay kill` of every row or of a paused row, which has no child, so no `kill` line; AR66), `owner-stop` (`relay stop`, its `owner-stop` line at the next poll, never draining; AR66), and `wake` at the wake (AR67), then from running `until`, `budget` or `sitting-failed` `usage-limit` when the wake stops the night; a paused row's late exit with a held line, the night paused or stopped, steps no pair, unless its own usage limit stops the night, which steps `sitting-failed` `usage-limit` (AR69 ruling 5), or its line broke an invariant, which steps `sitting-failed` `invariant` (AR70 ruling 4); a paused row's late verdict steps the night as any sitting's (AR70 ruling 3); a night stopped while paused halts each paused row as the wake's stop does (AR66). **Stop reasons** (thirty; A1's eleven plus nineteen): `queue-empty`, `count-reached`, `until-reached`, `budget-reached` (the night's USD or token budget), `stream-error`, `no-progress` (a row attempted twice in one night, or the same prompt hash as the row's last run; a paused row's continuation is not an attempt, since it never passes `PickIn`, AR67), `dirty-tree`, `no-commit`, `gate-failed-dependency` (every remaining row waits on a red or failed row), `ceiling-kill`, `wall-clock`, `origin-moved` (an alarm, always a stop), `tmux-gone`, `owner-stop`, `owner-kill`, `ledger-error` (the `spawn` line did not append, AR5), `measure-timeout` (the measure ran out of time and left a baseline unrun, AR10 §15; `budget` before AR38 act 2, which an old record still prints), `load` (the load breaker still open at its limit before a spawn, a sitting failure and a pre-check: `relay run` exits 2; AR10 §15), `invariant` (a runtime invariant broken, a sitting failure; AR10 §15), `orphans` (a survivor of the orphan sweep's three kills, or a stream still held after the exit, a sitting failure; D6, AR10 §15, AR13), `stalled-twice` (a second `stalled` row in one night: a stall can be the driver's as much as the packet's, so the first moves on and the second stops the night; R6 §2, AR13), `lock-moved` (the night's poll finds `relay.pid` gone or a new inode at its path, §8; AR22 act 2), `helper-storm` (a watchdog tick counts more than `night.MaxHelpers` `claude` processes among a row's seen descendants: the row's group and those killed at once, a sitting failure, no gate; §15, AR25 act 4), `usage-limit` (a `rate_limit_event` not allowed, or an `is_error` result naming a usage or rate limit) and `auth` (an `is_error` result naming a login, an expired token, `401` or `/login`): the account stops the whole night, a sitting failure, before the gate; `relay run` exits 1 and `relay clean --stale` keeps the worktree (run 10 ruling 1; AR17D act 0, its case now a weekly limit). A usage limit first asks `pauseFor` (AR65): it stops the night `usage-limit` at once, the `stop` line's `detail` naming why, while draining, on a weekly limit, on a model's limit with no reset; then by the guards (AR69 ruling 2; `pauseIn` carries `Count`, the night's pauses before the hit, and `Waited`, the reset the night last woke from, zero before a wake or after a fallback's): after a pause with no reset waited out and none now, the night having woken from a fallback wait (the probe, the fallback's wake refused again, armed only by that wake, AR71's fix round, F2: `refused again after the 30-minute wait, with no reset`), on a named reset not after the one waited out (`Limit.Named`, the event's `resetsAt` before the bound drops it, else the reset: `the reset <named> is not after the one waited out, <waited>`), and at the thirteenth hit (`MaxPauses`: `12 pauses tonight, the most a night takes`), each keeping its wake and source; then when the wake is at or past `--until`, and with no `--until` when the wake is over 6 h away (where a time-only text's reset, rolled to the next day, stops); else the night pauses until the wake (the reset plus 2 minutes, or 30 minutes with no reset, source `fallback`), kills and pauses every other running row of its scope. **The paused scope** (AR71): a model's limit with a reset pauses only that model's rows, the queue rows whose `model`, lowered and cut at every rune not a letter or digit, holds the limit's word as one piece (`ofModel`: `claude-fable-5-1` holds `fable`; `claude-opus-5-5` and `fablex-1` do not), and the others run on; any other pause holds every row (`DECISIONS.md` entry 12: the five-hour window still pauses every row). A later hit while paused, from a row outside the scope or a killed sibling, widens it: a model's adds its word to a scope of model words and leaves an every-row scope every row (a window's pause, then a sibling's model hit, stays every row: the AR71 hold's N1); any other makes it every row, killing and pausing the running rows as a window's pause does. The wake and the kept reset move only later; a fresh hit counts one more pause, a sibling's keeps the count; the wake clears the scope. While a model's scope holds, the loop picks as a running night does (AR64's N2): none once `--until`, `--max-sittings` or `--max-usd` is reached; busy the running and the paused rows, each keeping its slot and tree, so the wake's continuations stay within `--parallel`; the scope's rows held (`PickOptions.Hold`: never picked, counted waiting as a paused row is, never doomed nor blocked). It steps none of `until`, `count`, `budget`, `queue-empty`, `blocked` or an orchestrator's cut, and checks no window: the paused rows wait for the wake, which checks `--until` and `--max-usd`. Paused for every row, the loop picks nothing. `relay stop` while a model's scope holds steps `stopped:owner-stop` at once (AR66), and the rows outside it finish before the `stop` line as draining's do, since the loop collects every running row before it ends (AR64's N3). One wake serves the night: a model's rows paused beside a later window's reset wait for the later wake. A killed sibling's late exit naming its own usage limit, the night still paused, asks `pauseFor` with its pause's inputs, the count less that pause (AR69 ruling 5): a stop writes its `sitting` line without `limit: paused`, unlocks its stage and steps `sitting-failed` `usage-limit` with that detail, and the halt follows; a reset whose wake is later than the night's moves the wake and the kept reset there, with a second `pause` line (§5); a model's hit at the night's wake writes that line too, the wake unmoved (N1), as does a hit that widens the scope, naming the running rows it kills (AR71); else it pauses as before. Its count is its own pause's, less one, though a fresh hit outside the scope has since raised the night's, and its stop kills every running row, each failing `usage-limit`, as an account stop does (AR71's fix round, F1, F3). A held line collected on a running night (its kill outlasting the wake's slack) takes the ordinary path: the pause's account mark kept, `Paused` steps `gate-failed`, the row fails `usage-limit` with no `limit: paused`, its stage unlocked, and the account stop kills the running rows and stops the night `usage-limit` naming it, as before AR70 (AR70's fix round, F1). A held line that broke an invariant (its `reason` `invariant` after the write, no `limit`) halts the row: `Paused` steps `halt`, `failed: invariant`, no held stage kept, its stage unlocked, printed with its `relay resume` line, and the night steps `sitting-failed` `invariant`; the halt follows (AR70 ruling 4). A paused row's late outcome with no held line (a sibling killed in its gate, whose gate reads no context and ran to the end, or one failed on its own: `auth`, `orphans`) lands its verdict where it is collected, paused or not, never gated again nor given a child (AR70 ruling 3): its account mark cleared, `Paused` steps `gate-green`, `gate-red` or `gate-failed` by its state, its own reason kept, a green merged under the policy, its lines printed, and the night stepped as any sitting's (green and red keep a paused night paused; a failure stops it with its reason, `auth` killing the running rows); a skipped outcome stays paused for the halt. This amends usage-limit-resume r1 §2, which gated such a sibling again at the wake and kept its stage lock (probe B): its gate's whole verdict was read on a tree no child touches since, so a second gate on that tree and cut reads the same, and the lock serves only a row that continues (AR70 ruling 1). A kill that lands after the child's exit but before `RunRow` reads its cause still reads as the pause's kill, so that sibling holds its line and gets a part 2 with its acts done, where ruling 1 says never; the record's handling of a part with nothing left makes it cheap (its RESUME block lists the commits, the start hook keeps the stage's `head_before` so no `no-commit` nudge, and its gate judges the same cut), and NICE_TO_HAVE keeps it (AR70 ruling 9). A sibling never raises the count, and the wake makes the kept reset the one waited out (zero after a fallback's pause). The probe guard is armed at a fallback wake and disarmed once a sitting spawned at or after it ends without a usage-limit refusal (`ProbePassed`; AR69's fix round, F1; a verdict landing from a part launched before that wake does not disarm it, AR70), so a later refusal with no reset takes a fresh 30-minute fallback, counted toward `MaxPauses`. At the wake (AR67) the night writes a `wake` line and stops `until-reached` or `budget-reached` (never `count-reached`: `--max-sittings` is not read there, ar64-r1), or, every paused row checked before any continues, `usage-limit` naming the row whose tree moved (off the stage's branch, or its HEAD not descending from the stage's `head_before`: `<row>: the tree moved while paused`). A paused row whose outcome is still out at the wake (its gate outlasts the pause), the orchestrator's sitting included, is named by the `wake` line and neither halted, checked nor continued: it lands when collected, and the loop collects every outcome before the halt (AR70 ruling 5, which drops AR67's `<row>: killed in its gate` stop). Before those checks a paused orchestrator sitting is halted, never continued (AR68 ruling 4): `Paused` steps `halt`, `failed: usage-limit`, its stage unlocked, its tree kept, printed with no `relay resume` line; the loop then cuts the standing row's next sitting as orchestrator r1 §4 cuts any (`count` and `--max-sittings` as at any cut). Once that next sitting is cut (staged and spawned), `Night.Woken` holds the halted one: recovered, so the `stop` line's `red` and `resume`, the row's resume and `Clean` skip it, as `nextSitting`'s red list does for the sitting it cuts, and `orc.red` and `orc.stuck` never count it, since a halted sitting sends no outcome and never merges (AR68 ruling 5). A night that stops after the halt and before the cut (`--max-sittings` reached at the wake, the next sitting not staged) leaves it red: its `relay resume` line printed and on the `stop` line, the night not clean (AR68's fix round, F1). A stop at the wake halts each paused row `failed: usage-limit`, its stage unlocked and its tree kept. Else each paused row, in queue order, gets a continuation: `Paused` steps `spawn`, the row's account and kill marks clear, and the prompt and options its start rendered run a copy of its plan under a new session id and the budget its parts left (the queue row's turns and usd less each `sitting` line's turns and its `cost_usd`, or its `spawn` line's `usd` when unread; at least 10 turns and $5, or the row's own turns and usd when less, the dollars rounded down: AR69 ruling 3 amends usage-limit-resume r1 §2's floor, which a row of fewer turns or dollars would exceed) on the first stage's `Staged`: no stage, no `stage` line, no window, no pick and no count; limited again, it pauses again. An orchestrated night adds five after them (orchestrator r1 §4; AR32A act 4): `done` (the standing row's Next act reads `DONE:` and no row it added is ready, running or green and unmerged), `waiting` (`WAITING:`, or `DONE:` held, with no build row ready), `orchestrator-red` (a red sitting, once the ready rows ran), `merge-held` (a green sitting's merge failed with a plain error; the stop names its branch) and `queue-invalid` (the queue re-read at main after its merge does not load, validate or plan); its second stuck sitting in a row stops `no-progress`. **The rule that splits red from failed:** a packet failure (gate red) is the builder's; the night moves on to the next independent row. A sitting failure (`failed`) says the prompt or the driver is broken; the night stops with that reason. This keeps the brief's list and the stand-in's (d), (f), (g), (w) as night stops while gate reds behave as the brief says (D19, run 10 ruling 2).

**Gate reasons and the plan label (AR22; ADV13-1 to -8).** The gate's `unrun` gains `ref-moved` (the clone's fetch misses the bound sha, §6), `tool-moved` (a pinned tool's sum, link or `bin/` entry changed, §6) and `ledger-base-differs` (a hand gate's `stage` line names a base other than the queue row's, §5); the hand gate's `failed` gains `origin-moved` (the `stage` line's `origin_refs` differs from `ls-remote` now, §5). `unpinned-tool` is exit 2 at start: `effects.Pin` fails and every verb but `version` and the hook exits before it reads a queue (§6). The plan gains the label `unproven`: a branchless row a ledger line claims green prints `pending X (unproven)` (§5).

## §2 The packet schema

A packet is one markdown file under 9,216 bytes in the target repo's `design/packets/` (conventions §5; the S1 packet proves the shape): a title `# Packet <ID>: <title>`, a header table with six rows and six numbered sections.

| row | what the binary validates |
|---|---|
| from | non-empty; prose (the read list) |
| pin | a branch or sha; the queue row's `base` wins when both name one |
| wall | prose; must contain "this repo only" or a repo name |
| may touch | backtick spans, each a path or a per-segment glob (`*` inside one segment, a trailing `/` means everything below); "Nothing else" closes the set |
| acceptance | items split on `;`, each `` `shell line` <expectation> ``; expectations: `reads <value>` (the last non-empty stdout line equals value, a number or a backtick span), `reads <n> or more`, `under <n>`, `exits <n>`, `as main` (equal to the recorded baseline); `\|` inside a span is a pipe |
| budget | `<n> turns, <n>k context`; optional `, $<n>` |
| verify | optional, last (AR14 act 0; conventions §5, §9): one code span, the gate line, kept as `Packet.Verify`; two spans, a bare cell or the row out of place are refused; nothing reads it yet (the queue's `verify: auto` resolves the gate line). Test: `TestAR14_0_VerifyRowParses` |

Sections, in order, each `## N. <title>`: 1 What the source says (quoted), 2 Rulings, 3 Interfaces (signatures, not prose), 4 Findings that name this row, 5 Forbidden reads, 6 Report (capped). `internal/packet` parses the table and the headings and refuses anything else: a missing row or section, a size at or over the ceiling (9,216 bytes; `>=`, as doclint reads it; AR13 act 7, ADV6-16), an acceptance item without an expectation, a may-touch span with `**` (A1's finding: it never matches). Prose is never validated. Until `record` exists (D15) a packet's read list is `sed -n` ranges; conventions §8 governs after.

**Authored outside, copied in** (AR26; the owner's option A, 2026-09-24 ~18:36). A packet may be authored outside its repo: a helper the orchestrator spawns writes packets in batches into example-mac's `relay/prompts/`, and the stand-in's queue row names that file as its `prompt`. The builder's act 0 comes before any other act: act 0 copies it verbatim into `design/packets/<row>.md` and commits that file alone, so the repo keeps its packet; one already inside the repo is not copied. The Go queue's `packet` stays inside (§3; `queue.go` refuses a path that leaves the repo), so under the Go relay act 0 copies nothing. The copy is a packet by this section: `TestAR20_5_SpentStems` parses every file here, so the helper writes to this schema, the orchestrator's appended notes included (under the ceiling, six sections, acceptance on the allowlist). AR26's own copy did not parse (9,221 bytes, an appended `## 7.`, three items off the allowlist); act 0 kept the verbatim bytes in its commit and a second commit made the copy parse with the fewest edits (a read hint cut, `## 7.` demoted to `### 7.`, the three items moved verbatim to a `Stand-in only:` line). Record: DECISIONS.md entry 2.

**The packet writer's checklist** (AR28 act 5, landed by AR28B; AR26's copy that did not parse, run 5's D1). Before a packet leaves its writer, inside or outside the repo: under the ceiling (9,216 bytes by `wc -c`, the orchestrator's appended notes counted); the title `# Packet <ID>: <title>`; the header's rows in order (from, pin, wall, may touch, acceptance, budget, then verify when present) and the six sections in order, each `## N. <title>`; every acceptance line on the allowlist (`packet.allowlist`: `go test`, `grep`, `test`, `wc`, `cut`, `sed -n`, `git log|show|diff|rev-parse`, `cat`, `paste`, `bc`, `tail`, `head`, `echo`); one package per `go test`, named, with `-run '^Name'` and no trailing `$` (a prefix names the act's family of tests); no `./...` and no suite-wide line (the verify line is the gate, `make check`; an acceptance line is targeted, seconds on main); no home path, spelled out or by its tilde (hygiene reads a packet as it reads the repo, §12). `internal/packet` refuses a breach of the size, the title, the rows, the sections, the allowlist and `...`; the rest is the writer's care, and the builder's act 0 is where a breach shows first.

## §3 The queue schema

`relay/queue.yaml` in the target repo (D4). Strict YAML subset (D12; conventions §3): mappings, scalars, flat lists, comments; the binary ships its own parser with a corpus of accepted and refused documents and takes no dependency (D17, settled by the standing word, §14).

```yaml
version: 1
defaults: {model: claude-opus-5-5, turns: 100, context: 130000, usd: 15, wall: 4h,
           merge: branch-only, device: never, verify: auto}
words: ""        # the owner's words for every run, quoted verbatim into CONTEXT
rows:
  - id: a3-machine                      # the packet's file stem = branch = worktree name
    packet: design/packets/a3-machine.md
    depends_on: [a2-relay-design, ar1-relay-hooks]
    base: ar1-relay-hooks               # optional: cut off that row's branch, else main
    model: claude-opus-5-5              # per-row overrides of defaults
    budget: {turns: 100, context: 130000, usd: 15, wall: 4h}
    merge: branch-only                  # or merge-on-green
    device: never                       # or the owner's words, quoted verbatim
    parked: ""                          # a reason: listed, never validated, never run
    harness: [Makefile, scripts]        # optional: the paths main lays over the branch (§6)
```

Validation: ids unique and equal to the packet's stem; every packet exists and parses (§2); `depends_on` and `base` name rows or satisfied externals; no cycle (`base` counts as an edge, the stand-in's rule); `merge-on-green` only when the row's base is `main`; `device` is `never` or a non-empty string. A dependency is **satisfied** when the ledger holds a green line for it (any night on this machine), or when branch `<id>` has **landed** in the root, or when the row is in this queue and green tonight; never by ancestry, of the row's own base (a row cut off its dependency's branch would satisfy itself, AR4) or of the branch itself (a fresh branch's tip is its cut, an ancestor of `main`: §16 gap 1). An id that is none of these is pending; unknown to both the queue and git is invalid. The queue replaces NEXT (the brief); `doclint` refuses a NEXT file.

**Landed** (AR13 act 8; the model's `BranchTipMovedBeforeLanded`): a merge commit on `main`'s first-parent line has the branch's tip as a later parent (`effects.Git.FirstParentMerged`, `git log --first-parent --merges --format=%P main`), and that tip is not the cut the stage recorded (`head_before`), when a stage line records one. The relay merges `--no-ff` (D22), so its merges read landed; a branch `main` fast-forwarded to does not, nor a branch cut off a merged tip and never moved. `night.landed` is the one reading: the plan's own-id `landed` state, `satisfied`, `DepSatisfied` (the hand gate's invariants) and the prompt's unmerged list. Tests: `TestAR13_8_FreshBranchNotLanded`, `TestAR13_8_FirstParentMergeLands` (a real git root under `t.TempDir`).

**The harness** (AR20 act 2; ADV11-4, the decisions handover inside D2): `harness:`, in `defaults` and per row, is a flat list of repo-relative paths a branch may not use to judge itself (§6's overlay and guard). Unset, it is `[Makefile, scripts]`; a row's list replaces the defaults', never adds to them; the make spellings (`Makefile`, `GNUmakefile`, `makefile`) are always added and always first (`queue.HarnessOf`: make reads `GNUmakefile` before `Makefile`). A path that is absolute or climbs out of the repo is refused at parse. decisions' queue names `[Makefile, scripts, tests/run.py, tests/gates.py, tests/skips.allow]` (AR24; decisions' change-log d15), so a builder who may touch them cannot edit the check that judges it: the harness is what judges a branch, never the code it builds; naming decisions' package, or its `tests` dir whole, would lay main's copy over the branch's own code and revert it. Tests: `TestAR20_2_HarnessListFromQueue` (queue and gate).

**The measure's budget** (AR38 act 1; §15): `measure_seconds`, in `defaults` only, is an integer from 60 to 14400 (anything else refuses the queue, naming the key), the budget of the measure on main when `--measure-seconds` is not given, with 600 when neither is.

- **Ids** (R6-23; AR7-9, -10; ADV10-19): an id matches `^[A-Za-z0-9][A-Za-z0-9._-]*$` and names a branch: `git check-ref-format --branch` passes it (no `..`, no trailing `.`, no `.lock` suffix, never `HEAD`), and it is never a base (`main`, or its own row's); `HEAD`, `main` and `.lock` fold case. Ids are unique case-folded (two rows differing only in case are one worktree on a case-insensitive disk), and a row's packet is a path inside the repo, never absolute or climbing out. A relative path resolves against the queue's repo, never the cwd (AR14 act 2; the owner's ruling 2026-09-23 14:55 (1)); the key is `packet`, no `prompt` alias. Tests: `TestAR14_2_RelativePacketResolvesAgainstRepo`, `TestAR17D_4_RefShapedIds`.
- **The orchestrator row** (orchestrator r1 §2; AR32A act 1): four row keys, `kind` (`build`, the default, or `orchestrator`), `prompt` (the standing brief, present at main), `sections` (the brief's sections the body line names) and `may_touch` (guarded paths it may change). ## §6 The gate

Deterministic, zero tokens, in the driver (D2). The `Gate` is a record of facts gathered by effects and one pure function `Decide(Gate) Result` (`green`, `red`, `failed`, `unrun`), so `relay gate <row>` by hand and the night's own gate are the same code. Checks, in order, each a `gate` ledger line:

1. `exit`: a result event was seen and `is_error` is false; else `failed: stream-error`.
2. `commit`: HEAD moved from `head_before`; else `failed: no-commit`.
3. `clean`: `git status --short` in the worktree is empty; else `failed: dirty-tree`.
4. `origin`: `git for-each-ref refs/remotes` equals the snapshot taken at stage, and a fresh `git ls-remote` per remote equals `Staged.OriginRefs` (a push by URL moves no tracking ref; AR17A act 0, ADV10-3; a remote stage could not read is `unknown`, the check skipped `ls-remote`); else `failed: origin-moved` and the night stops. ## §8 Concurrency

`--parallel N`, default 1, at most `runtime.NumCPU()`: over the cores is usage, exit 2, before any plan (AR13 act 5; ADV6-13). Two rows may run at once only when they are in different repos, or in different worktrees of one repo and neither is the other's `base` or dependency. Never two sittings in one working tree: a lock file per worktree path in the state directory (`<state>/locks/<sha1 of path>`, created `O_EXCL`), held for the sitting, is the guard; it holds `pid<TAB>started<TAB>worktree` (`night.LockHolder`, `started` as `Procs.Started` reads it), and a lock whose pid is dead or runs with another start time is stale (`night.StaleLock`): `Stage` reclaims it with a `lock-reclaimed` line, and `relay clean --stale` removes it (AR13 act 4; R6 §4). A lock of the older `pid worktree` shape is stale only when its pid is dead; with no `Effects.Procs` no lock is stale; and `plan` refuses a row whose worktree or branch already exists. Those are the same two tests `Stage` runs (AR58), on every build row the plan would make `ready` or `pending`. A row that fails either reads `refused`, with its reason in stage's words. That reason is a row problem, never a plan one, so the plan stays valid and the night runs the other rows. A refused row is never started. From the night's open on it is what a stage-skipped row was: its `skip` line reads `stage <id>: <reason>`, the report and status list it with its worktree, and its dependents are doomed. Behind a failed dependency the row is itself doomed, so the stop and the exit are a stage skip's (AR58 hardening round). The standing orchestrator row is exempt, since `Stage` tests each of its sittings. The root working tree is never a sitting's cwd; merges use the root and are serialised in the night's loop. A live claude process whose cwd is inside the repo (the stand-in's `pgrep` and `lsof` probe) is a printed warning at `plan`; one whose cwd is the row's own worktree is a refusal. The probe (`night.LiveClaude`) runs under `night.LiveClaudeTimeout` (30 s; R6 §4): past it lsof is killed and the answer is unknown, an error, so `Stage` and the gate refuse (AR13 act 5). Worktrees live at `<repo>/.claude/worktrees/<id>` on branch `<id>` (the stand-in's proven layout, excluded from status via `.git/info/exclude`) and are removed only by `relay clean --merged` or `--stale`, never by the night.

**One relay per account, not per env** (AR20 act 4; ADV11-9, a fork-storm door). The ancestor pid file (§15) lives at `<account home>/.local/state/agent-relay`, the home read from `os/user` (`night.UserHome`, `night.PidDir`), never from `$HOME` or `XDG_STATE_HOME`, so a child that changes its env, or runs under `env -i`, still finds the live holder; a relative state root is refused, exit 2. Tests point the home at temp dirs (`TestMain`; a built binary by `-ldflags -X` into `PidHomeLink`). The merges the gate counts (§6) are held in one map per process keyed by the resolved root: a sibling's merge under `--parallel` advances its root's expected main, and a merge in another root never does. Tests: `TestAR20_4_NestedByEnv`, `TestAR20_1_MainBoundEveryRow`.

**The account lock is a port** (AR22 act 2; ADV13-4, a fork-storm door; ADV13-14's `ps`, pid 0 and `relay gate`; AR21 act 2's holder rule, ADV12-3, -8). `run`, a measuring `plan` and `resume` refuse ANY live holder, ancestor or not, exit 2, so a detached relay (`( relay & )`) or a second night from another shell is refused. No bypass flag: a flag a sitting can type is no lock, and `--parallel` is the concurrency door; a refused `resume` with a row prints the line it would exec, as `--print` does. The file tools are denied the pid dir (§10). It supersedes the pid file as the lock above, and AR21's `flock` on `relay.pid` with it (its paragraph went at AR24; ADV14-10): the lock is a TCP listener on 127.0.0.1, port `20000 + uid % 10000` (below both ephemeral ranges), no `SO_REUSEADDR`, close-on-exec; `ExecHolding` clears `FD_CLOEXEC` on that one fd under `syscall.ForkLock` just before resume's exec. The kernel frees it on death, so no sitting can unlink it (ADV13-4 closes). `relay.pid` (written temp and rename, closing the pid-0 window) only names the holder; the night re-stats it each loop pass, and a missing file or a new inode stops the night `lock-moved`. A taker that gets the port never replaces a `relay.pid` naming another live holder (its pid live, its `lstart` the line's or unreadable, since a `ps` that fails is never read as a dead pid): it frees the port and refuses, exit 2, naming that holder, the path and its own port, while a dead or reused pid's file is replaced as crash recovery (AR36 ruling 1). A refusal names a pid only when it is live and its `ps lstart` matches, else "held and relay.pid names no live relay". `relay gate` takes the lock; `ps` runs pinned (§6). The port is a Go var (`night.LockPort`), and for built test binaries a link-time `-X <module>/internal/night.LockPortLink=<port>`, never env. A binary linked with `LockPortLink` and no `PidHomeLink` refuses to resolve its pid dir, since `PidDir` reads the account's home from the user database whatever `HOME` says (AR36 ruling 2). Residuals: any local program holding the port refuses the night (fail closed); after a connect and the holder's death, `TIME_WAIT` can refuse the next taker for up to about a minute (fail closed); the lock is advisory against a child that builds its own relay with its own port link (ADV13-13); the kept fd passes to resume's descendants (ADV13-12, deferred, §15). Tests: `TestAR22_2_*` (§11).

**The wildcard hold** (AR24 act 2; ADV14-4, review-adv14 test 3). Measured before: while a relay held `127.0.0.1:P`, a listener on `:P`, `0.0.0.0:P` (`python3 -m http.server P`, which the Bash guard allows) or `nc -l P` still bound, and after release it refused every later night, naming nobody. The lock now also binds `0.0.0.0:P` (tcp4; `SO_REUSEADDR`, only to pass its own `127.0.0.1:P`, never `SO_REUSEPORT`) and `[::]:P` (tcp6, `IPV6_V6ONLY`; skipped when the stack has no IPv6), each bound and never listening, so nothing is exposed to the LAN; each is close-on-exec and kept across resume's exec (`ExecHolding`) as the first is. `127.0.0.1:P` stays the identity: the refusal, `relay.pid` and the model read it alone. `EADDRINUSE` on any of the three refuses the night (`NestedError`), as today. Linux refuses an overlapping wildcard bind itself, so none is held there. Residual: a squatter bound before a start still refuses the night naming nobody (fail closed); its pid in the refusal is deferred (§15). Tests: `TestAR24_2_WildcardAndGowork`, `TestAR24_2_WildcardHeld` (§11).

**A quote ends where the shell ends it** (AR43 acts 1 and 2; AR42's review, F1 and F2). Two readings joined the shell reader. ## §16 The model

The night is modeled in TLA+ and checked by TLC, so a fork storm is a found trace, never a surprise (the owner, 2026-09-23 12:35; AR11). Files, all in `design/tla/`: `Night.tla` (plain TLA+, no PlusCal: §1's machines, §6's gate, §7's spawn, §8's lock, §15's bounds), `Night.cfg` (the design of record), `Storm.cfg`, `Storm-run.cfg` and `Storm-detached.cfg` (the storms), `storm-trace.txt`, `storm-run-trace.txt` and `storm-detached-trace.txt` (TLC's counterexamples, cut from its `Error:` line to the last state), `check.sh` (what `make tla` runs). `make tla-tools` fetches `tla2tools.jar` once into the gitignored `design/tla/.tools/`; `make tla` never fetches (the jar absent: it says so and exits 2), runs TLC with `-workers 4` over the four configs under `JAVA` (brew's openjdk; `/usr/bin/java` is a stub), and is not in `check`. `TLA_JAR` names the jar relative to where `make` runs, so a worktree borrows the main checkout's (`make tla TLA_JAR=../../../design/tla/.tools/tla2tools.jar`, AR21 act 7).

**Shape.** Two rows; pid 1 is the relay at depth 0; every process is a slot `[kind, parent, group, depth, alive, holdsStdout, spawnedOpen, row]`, a pid never reused while its group lives. An `escaped` process (AR17C) is a measured line's setsid daemon: its own group, `parent` the session it left (a pid never reused while it names one), swept by the line's end and by the trap; a SIGKILLed relay's escapee is outside the model, as groups.json records groups, not sessions. The relay's own steps (validate, measure, spawn, the wall, sweep, gate, merge, the breaker's first read, the night's moves) are one action, `NightStep`, weakly fair; the child (`Progress`, `ChildExit`, `NestedRun`, `DetachedRun`), a measured line (`LineStartsPlan`), the load, the owner and a signal or kill to the relay (`Signal`, `RelayDies`) get no fairness. `--parallel 1`, the default. The load moves only while a breaker or a measured line can read it, and rises only while the breaker is closed.

**Constants** (`Night.cfg`): `Rows = {r1, r2}`, `MaxProcs = 5`, `MaxDepth = 3`, `MaxWait = 2`, `Guard = TRUE`, `RunGuard = TRUE`, `LinesMayPlan = TRUE` (a measured line may run `relay plan`, so the guard is exercised), `PidRule = "any"` (every live holder of `relay.pid` refuses, AR21 act 2); the load scaled to its three regions, `MaxLoad = 2`, `OpenAt = 1`, `CloseAt = 1`, and the watchdog to stall-before-wall, `StallAt = 1`, `Wall = 2` (AR11's 5/4/2 and 2/3 ran six minutes; these ran about 70 s, 666,949 distinct states, and have grown since: AR21 act 7 measured 5,434,561 in 14 min 12 s, four workers under a load of six; `DetachedRun` adds none under `"any"`, since pid 1 holds while it is up).

**Properties.** `FairSpec` is `Spec` with `Poll(r)`, `Stall(r)`, `BreakerPoll`, `NightStep` and `Reap` (a killed relay's next start) weakly fair; `LoadFair` adds `LoadDown`, the assumption that a load the breaker waits on falls. `Night.cfg` checks all four under `LoadFair`; under `FairSpec` alone the last three hold and `OpenBreakerEventuallyCloses` fails, as it must (checked by hand, 2026-09-23).

- `StalledChildEventuallyKilled`: a child at `StallAt` is dead; `night.Watchdog`, `TestAR10_6_StallKillsGroup`.
- `OpenBreakerEventuallyCloses` (`LoadFair`): an open breaker closes; after a trip, once the load falls.
- `OpenBreakerEventuallyResolves`: an open breaker closes or trips at `MaxWait`; `night.Breaker`'s `Max`, `TestAR10_5_BreakerOpensAndCloses`.
- `EveryRunnableRowEventuallyGatedOrParked`: a ready row reaches `landed`, `green`, `red`, `failed` or `skipped`, or its killed relay is reaped (the next night plans it again); the wall, the watchdog, the breaker's `Max` and the halt, `TestAR10_6_WallNeverZero`.

**The storms.** `Storm.cfg` (`Guard = FALSE`, `LinesMayPlan = TRUE`, the one invariant `NoNestedMeasure`): TLC finds a nested plan measuring at depth 2 in four states (Init, `PlanValidate`, `Measure`, `LineStartsPlan`). `Storm-run.cfg` (`RunGuard = FALSE`, the one invariant `NoNestedSpawn`): TLC finds a child's `relay run` spawning its own child in seven (… `Spawn`, `NestedRun`). `Storm-detached.cfg` (both env guards on, `LinesMayPlan = FALSE`, `PidRule = "ancestors"`, the rule before AR21, the one invariant `NoNestedSpawn`): TLC finds a child's detached `relay run` past the ancestors-only pid file spawning a second night's child in seven (… `Spawn`, `DetachedRun`), ADV12-3's fork-storm door. `make tla` asserts the fourteen names are defined, `Night.cfg` clean, the four storms violated, by grep on TLC's lines (exit codes are not enough), and ends `tla: ok`; otherwise it exits 2 naming the config. Four workers pick among the shortest traces, so each fresh trace goes to `.tools/` and the committed one is rewritten only when absent or under `TLA_TRACES=1`; its depth must equal the fresh one's, so a gate's rerun of `make tla` leaves the tree clean.

**The lock's identity** (AR22 act 6; ADV13-4). `LockKind` is `"port"` or `"path"`; each process slot carries `unlinked`. `Unlink(c)`: a live sitting removes relay.pid's name, marking every live holder; `HolderDies(h)`: a holder other than the night's relay (whose death is `RelayDies`) dies and the kernel frees its lock. `Seen` is every holder under `"port"` and only the holders not unlinked under `"path"`; `PidGuard` reads `Seen`. `OneHolder` (`Cardinality(Holders) <= 1`) joins `Night.cfg`, clean under `LockKind = "port"` (the port lock survives `Unlink`): 10,860,607 distinct states in 28 min 16 s, four workers (AR22 act 6, by hand). `Storm-path.cfg` (both env guards, `PidRule = "any"`, `LockKind = "path"`, the one invariant `OneHolder`): TLC finds two holders 8 states deep (a sitting unlinks relay.pid, then its detached relay flocks a new file at the path), `storm-path-trace.txt`.

**Modeling choices.** `waited` counts the night's breaker polls, not one wait's, and the waiter's first read is the relay's step: as the environment's step, a load bouncing across `OpenAt` starved both the spawn and the open (TLC's first lasso), which Go cannot do because its `Wait` reads once and acts. `DetachedRun(c)` (AR21 act 7, ADV12-3) is a child's `relay run` with its env stripped (`env -i`, `setsid`, a launch agent): no `RELAY_ROW` and no depth, so neither the run guard nor the hook sees it, and its parent is launchd, never an ancestor; the relay and its first child start in one step, as `NestedRun`'s do. `PidGuard(par)` is `night.PidFile`: `Holders` are the live relays (pid 1 while `relaySt = "up"`, a dead holder's flock dying with it); `"any"` refuses while one lives, `"ancestors"` only a holder on the comer's parent chain (`Above`). TLC's bound: `DetachedRun` only while the night's relay is up, since a relay started after its death is the next start, `Reap`'s step. A stream held by a live process of the row keeps the row running after the child's exit until the wall. SIGKILL ends every member of a group; a process that left the group is outside it. The gate is one step; a rerun line that plans is `LineStartsPlan`'s case, not modeled again. A green gate records the tip it measured (`checks[r].at`); `LateCommit` lets a live process of the row move the tip after it, and `Merge` takes only the recorded tip, and only a `green` gate: a merge whose verify is red, unrun or skipped never lands (`MergedShaIsGated`, AR13 act 1). Main is `mainSha`, a counter (AR17A act 0, ADV10-1): `Spawn` records it as the row's expected main (`checks[r].main`, `Staged.BaseSha`), the relay's own `Merge` moves it and every unmerged row's expectation with it (`gate.expectedBase`), and `MoveMain(r)`, a running child's `update-ref` once a night, moves it alone; a gate that finds main off its expectation is `red` `main-moved`, and `Merge` lands only onto the expected main (`NoMergeAfterMainMoved`). The relay's life is `relaySt` (AR13 act 2, ADV6-2): `Signal` (the trap: every recorded group killed, every row not terminal failed or skipped `owner-kill` with its sitting line, the night done `owner-kill`), `RelayDies` (a kill past the trap: the night done `relay-dead`, nothing written, the children live on) and `Reap` (the next start: every recorded group, a row's child group and the measured line's, killed); every relay step (`NightStep`, `Poll`, `Stall`, `BreakerPoll`, and `ChildExit`, whose exit line is the relay's) needs a live relay, the breaker's wait ends with it, and a start time that no longer matches is left to `FreePids` (no pid reused while its group lives).

D1 and the owner's ruling of 2026-09-22 12:55: the resume door must be obvious, so `/agent-relay:resume` is the first command the plugin description names, and `status`, `resume` and `report` each print `relay resume <row>` for every red or failed row. Inside a Claude Code session a nested interactive `claude --resume` is never run: the command prints the exact line and the worktree path for the owner's own terminal. D11: one marketplace per repo, `.claude-plugin/marketplace.json` as A1 made it, brought to conventions §2's fields. D15: `record` ships in claude-code-session; this plugin ships no reader and no `/agent-relay:read`. R25-91 (3): no `dependencies` in `plugin.json`; respeak and the session are optional and detected, never required. Rule 8 (session budget): `builder` and `adversary` run on `claude-opus-5-5` (the owner's word); `attendant` runs on `sonnet` (a reader, not a builder; the owner may say otherwise). `claude plugin validate plugin/` stays in `make check`. No binary change: every command reads what A8's `--json` shapes already carry; a missing field is a handover line, never a Go edit.

## 3. Interfaces (signatures, not prose)

- A command file `plugin/commands/<verb>.md`: frontmatter `description` (one line), `allowed-tools: Bash(relay:*)`, `argument-hint`; the body under thirty lines: run `relay <verb> --json $ARGUMENTS`, print the fields that matter in plain lines, and when the exit is 3 or the binary is absent say `relay is not on PATH: make install`. `plan`: rows, states, problems, the spawn line per row. `status`: the night, its state and reason, one line per row (state, turns, context, cost), `Next`, then every `Resume` line verbatim. `resume [<row>]`: from `relay status --json`, the row's `Resume` line and worktree, or every red or failed row when none is named; ends with "run it in your own terminal, not here". `gate <row>`: exit and each check's `name`, `status`, `main` and `branch` last lines. `report`: `relay report` markdown; when the `respeak:respeak` agent is available in the session, hand it the markdown in `technical` mode and print the narrative, else print the markdown verbatim. `doctor`: each check as `ok`, `warn` or `FAIL` with its detail.
- An agent file `plugin/agents/<name>.md`: frontmatter `name`, `description` (when to use, under 300 chars), `model`, `tools`, `maxTurns`; the body is the persona. `builder` (`claude-opus-5-5`; Read, Edit, Write, Bash, Glob, Grep): one packet is its whole scope, commits per item, never pushes, amends, rebases or touches a device, writes its charter, reports the acceptance table. `adversary` (`claude-opus-5-5`; Read, Grep, Glob, Bash): read-only over a named slice, runs tests, numbers findings with a reproducing test or shell line, fixes nothing, reports observations apart from findings. `attendant` (`sonnet`; Read, Bash): runs `relay status --json` and `relay report --json`, reads the ledger's lines by `jq`, never the transcripts, answers "where is the night" in under twenty lines with every resume line.
- `plugin/.claude-plugin/plugin.json`: `name` `agent-relay`, `version` unchanged (the tag is the owner's), `description` under 200 chars naming the door first, `author {name}`, `homepage` and `repository` as `https://` plus the module path in `go.mod`, `license` MIT, `keywords`; no `dependencies`, no `userConfig`. `.claude-plugin/marketplace.json`: the same description and version.
- `scripts/doclint` rule `plugin`: every `plugin/commands/*.md` under 31 lines with `description` and `allowed-tools` in its frontmatter; every `plugin/agents/*.md` with `name`, `description`, `model`, `tools`; the command set equals §10's six; the docstring lists the rule.
- Tests: the acceptance lines are the tests (the plugin is markdown and JSON); `make check` runs `claude plugin validate plugin/` and `scripts/doclint`.

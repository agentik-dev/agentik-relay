## 1. What the source says (quoted)

relay-r1 §11: "Conventions §4 binds: every invariant is one named test, and a runtime guard too where it can be; the test names the guard." Its list: `TestStepMatrix`, `TestNightMatrix`, `TestActions`, `TestNoPushPath`, `TestMergeNeedsGreen`, `TestOneSittingPerTree`, `TestLedgerBrackets`, `TestEveryStopHasReason`, `TestTemplateHashRecorded`, `TestPlanEqualsRun`, `TestOriginMovedStops`, `TestLedgerHoldsNoPrompt`, and "End to end: a fake `claude` ... a night over a two-row queue in a temp repo asserts the ledger, the merge sha and the stop reason. No network in tests." §5: "No message content, ever; the only free text is the result tail and each check's last line, capped at 200 bytes." §7: "with every `CLAUDE*` variable stripped from the environment"; "at 100% SIGTERM, thirty seconds, SIGKILL". §8: "Never two sittings in one working tree". Session-budget rule 8: "Concurrency: THREE Opus at a time".

## 2. Rulings

Rule 8: the sitting is itself Opus, so two review agents at most run at once; the third slice starts when one returns (the owner may raise it to three). A finding is real only with a reproducing line: a test that fails before the fix and passes after, or a shell line with its exit; everything else is an `observation` and is never fixed. Fixes stay inside "may touch"; a fix that would need a file outside it, a design change, a new dependency, a flag or a verb the design does not name is a `handover` finding with its consumer. The design of record is not the reviewer's to change: where the code follows the design and the design is wrong, the finding is a `handover` naming the section. A finding the coordinator disagrees with after reproduction is `refused` with one line why. The `--json` shapes and exit codes are frozen (AP1 reads them). No new verb, no wording work (UX1's), no README (AR3's).

## 3. Interfaces (signatures, not prose)

- The three slices, each one Agent call with the same brief (below) and its own file list: `machines-gate` = `internal/relay/`, `internal/gate/`, `internal/night/stage.go`, `internal/night/schedule.go`; `parsers-effects` = `internal/yaml/`, `internal/packet/`, `internal/queue/`, `internal/effects/` (all but `spawn.go`), `internal/prompt/`; `spawn-stream-night` = `internal/effects/spawn.go`, `internal/stream/`, `internal/night/` (all but the two files above), `cmd/relay/`. Read `ls -R internal cmd` on the base branch at build time and place any file not listed here in the slice its package names.
- The brief each agent gets: model `claude-opus-5-5`, tools Read, Grep, Glob and Bash for `go test`, `go vet` and `git log` only; the persona of `plugin/agents/adversary.md` when present; the questions, in order: which §11 test is missing or asserts less than its name; where an error is swallowed; where a ledger or notice line could carry a prompt byte or a home path; where a kill, a timeout or a lock can race; where two rows could share a tree; where an unrun check passes; where `--json` and the printed line disagree; where a test touches the network, the real state directory or a real `claude`. The return: findings as `severity | file:line | claim | reproducing line`, then observations; under 3,000 words.
- `design/review-ar2.md`: `# AR2: the adversarial review of <base sha>`, one `## <slice>` per slice with its agent's turns and cost, then `### AR2-<n>: <claim> (fixed <sha> | handover: <consumer> | observation | refused)` with severity (`blocking`, `high`, `low`), file and line, the reproducing line, and the fix's test name; findings numbered across slices in the order they were reproduced; a closing `## Totals` (findings by status, agents by cost).
- Each fix: one commit `AR2-<n>: <one line>`, carrying the reproducing test (named `TestAR2_<n>_<Short>` when new) beside the fix; `make check` green after every commit.
- The coordinator's loop: start two agents; on a return, reproduce every finding itself before it counts; start the third agent; fix in severity order, blocking first; a finding whose fix breaks another test is `handover`, never a second fix.

## 1. What the source says (quoted)

relay-r1 §9: `attach [<row>]` "tmux attach to the night's session or the row's window; without tmux, `tail -f` the row's log"; `doctor`: "`tmux` (a warning when absent: file windows)"; the user file holds "`ntfy: {url, topic}`, `tmux: auto`". §7: "at 80% of the row's context a `ceiling` line and a notify". §5: "No message content, ever" beyond the capped tails. §1 names `tmux-gone` among the stop reasons. D16: "keep the file-window fallback (`--no-tmux`, one log per row, `attach` tails it) so a night never depends on it." D23: the user file "holds ntfy and tmux."

## 2. Rulings

D16 is UNRULED (tmux is absent on the build machine). Cut: the file-window fallback is the built and tested mode; tmux sits behind an interface with a fake; the real path is one test skipped when `tmux` is not on PATH. `tmux` in the user file takes `auto` (use it when present, the default), `never` (`--no-tmux`) or `required`; a session lost under `auto` is a notify and a fall back to file windows for the rest of the night, and under `required` it is the `OnTmuxGone` event and the `tmux-gone` stop §1 names. If A8 left `draining` + tmux-gone unmapped (A3's handover), map it to the fallback, never a panic. D23 as recommended. A window is a viewer over the row's log (`tail -f`), never the child's terminal: A7's spawner is unchanged. Ntfy carries the event's fields only, never a prompt or a message; a failed post is a log line, never a stop. No plugin work: AP1's.

## 3. Interfaces (signatures, not prose)

- `internal/effects/tmux.go`: `type Tmux interface{ Present() bool; NewSession(name, dir string, argv []string) error; NewWindow(session, window, dir string, argv []string) error; Alive(session string) (bool, error); AttachArgv(session, window string) []string }`; `OSTmux{ LookPath }` runs `new-session -d -s`, `new-window -d -n -c`, `has-session -t`; `FakeTmux{ IsPresent bool; AliveAfter int; Calls []string }` in `fake.go` records calls and reports `Alive` false after `AliveAfter` calls. `TestRealTmux` (`t.Skip` without `tmux` on PATH) makes and kills a session `relay-test-<pid>`.
- `internal/effects/notify.go`: `type Notify interface{ Send(n Notice) error }`; `type Notice struct{ Event, Night, Row, Title, Body string; Priority int }`; `Ntfy{ URL, Topic string; Client *http.Client }` posts `Body` to `URL/Topic` with headers `Title` and `Priority`, five-second timeout; `LogNotify{ W io.Writer }` writes one line; `Multi(...Notify)`; `FakeNotify{ Sent []Notice }` in `fake.go`. `func Notices(event string, fields map[string]any) (Notice, bool)` maps `night-open`, `sitting`, `ceiling`, `stop`, `night-close` to a notice (priority 4 for `ceiling` and `stop`, else 3), refuses every other event; the body is the fields' names and values, capped at 200 bytes; a red or failed `sitting` body ends with `relay resume <row>`.
- `internal/effects/config.go`: `Tmux` keeps its string; `func (c Config) TmuxMode() (string, error)` returns `auto`, `never` or `required`, an error otherwise (`doctor` lists it under unknown values).
- `internal/night/windows.go`: `type Windows struct{ Mode string; Session string; Tmux effects.Tmux; State string }`; `func Open(tm effects.Tmux, mode, night, state string) (*Windows, error)`: under `auto` or `required` with `Present`, `NewSession("relay-<night>", state, ["sh", "-c", "while :; do clear; relay status; sleep 5; done"])`; `func (w *Windows) RowWindow(row, logPath string) error` opens `tail -f <log>` in window `<row>`; `func (w *Windows) Check() (fallback bool, gone bool)` after every loop event: `Alive` false under `auto` sets `Mode` to `never` and returns `fallback`; under `required` returns `gone`. The row log path is A8's (read `internal/night/` on the base branch); when none exists, `<state>/nights/<night>/<row>.log`.
- `internal/night/night.go`: `NightOptions` gains `Tmux effects.Tmux; Notify effects.Notify; TmuxMode string`; the loop calls `Open` at `night-open`, `RowWindow` at `stage`, `Check` after every event, `Notify.Send` for every event `Notices` accepts. `run.go`: `RunOptions.Notify` is fed by the same `Notify`.
- `cmd/relay/main.go`: `attach [<row>] [--print]`: the latest night's `status.json` names the session and the row logs; with tmux alive, `syscall.Exec(AttachArgv)`; without, `tail -f <log>`; `--print` prints the line it would run, exit 0; an unknown row or no night exits 2. `doctor`: the tmux line is a warning under `auto`, red under `required`, ok under `never`; a new `ntfy` line reads `configured <topic>` or `unset: notices go to the log`, no HTTP. `run --no-tmux` forces `never`. `Ntfy` is built from `LoadConfig` in `main.go` only; tests use the fakes.
- Tests: `TestFakeTmuxWindows` (a one-row night over the fake claude with `FakeTmux{IsPresent: true}`: one session, one `status` window, one row window, the calls in that order); `TestTmuxGoneFallsBack` (`AliveAfter: 1` under `auto`: a `LogNotify` line, the night ends `stopped:queue-empty`); `TestTmuxRequiredStops` (`required`: `stopped:tmux-gone`); `TestNotifyEvents` (the five events produce five notices, `turn` produces none); `TestNotifyNoContent` (no notice body holds a byte sequence of the prompt beyond the caps); `TestNtfyPost` (an `httptest` server receives the path, the `Title` and `Priority` headers); `TestAttachWithoutTmux` (`--print` reads `tail -f <log>` with the row's path).
